# `lib/modules/` — USB HID kernel modules (kindlepw2 / `3.0.35-lab126`)

The plugin copies USB HID support into KOReader so it no longer depends on
KindleLazy loading modules at boot. The native helper (`lib/ckm_input.so`) runs
`insmod` on these files in this order during plugin init:

1. `hid.ko`      — USB HID core
2. `usbhid.ko`   — USB HID input binding (depends on `hid`)
3. `mousedev.ko` — optional `/dev/input/mice`; a page-turner without a mouse works fine without it

The three files are **committed on purpose**: a clone is enough to install a
working plugin, with no "go fetch the modules" step. They cannot be built here —
they have to match the kernel that runs on the device.

PW3 (`kindlepw2`, kernel `3.0.35-lab126`) is the **only supported device**: the
helper in `lib/ckm_input.so` is built for that same ABI. The section at the
bottom is only for someone porting the plugin to another Kindle.

## Provenance

| | |
| --- | --- |
| Device | Kindle PW3, kernel `3.0.35-lab126 preempt mod_unload ARMv7 p2v8` |
| Source | [llakssz/KindleLazy](https://github.com/llakssz/KindleLazy) — `bin/hid.ko`, `bin/usbhid.ko`, `bin/mousedev.ko` on branch `master`; our three files are byte-identical to those (sha256 checked 2026-09) |
| Also ships as | the `KindleLazy` KUAL extension on the device, i.e. `/mnt/us/extensions/KindleLazy/bin/`, which is where they were first taken from |
| Imported | added to the initial commit of this plugin (2026-08); this repository is now the reference copy |
| Upstream | stock Amazon kernel modules — mainline USB HID drivers (`hid.ko`: Jiri Kosina / Vojtech Pavlik / Andreas Gal), all three `license=GPL` |
| Built with | `GCC: (Linaro GCC 4.8-2014.04) 4.8.3 20140401 (prerelease)` |

Every blob is pinned by `SHA256SUMS` in this directory, and
`scripts/check-artifacts.sh` verifies those hashes (plus the `lib/ckm_input.so`
ABI) on every run.

## Tracking upstream

The committed blobs follow `llakssz/KindleLazy` `bin/` on `master`. To see whether
upstream has moved:

```sh
for f in hid.ko usbhid.ko mousedev.ko; do
    curl -fsSL "https://raw.githubusercontent.com/llakssz/KindleLazy/master/bin/$f" \
        | shasum -a 256 | sed "s|-|$f|"
done
```

Compare that with `SHA256SUMS`. Upstream builds its modules against a specific
kernel, so only take a newer file if its vermagic still matches the target
device — check `cat /proc/version` before swapping.

## Replacing them (only if you port to another device)

A vermagic mismatch is easy to miss: `insmod` simply fails, KOReader logs
`insmod ... failed` and no input device ever shows up. When moving to another
Kindle:

1. read the target kernel on the device: `cat /proc/version` (or `uname -r`);
2. get that build's `hid.ko`, `usbhid.ko`, `mousedev.ko` — from
   [KindleLazy](https://github.com/llakssz/KindleLazy)'s `bin/` (pick the branch
   whose modules match that kernel), from the device's `/lib/modules/`, or from
   the matching firmware image;
3. copy them here, then refresh the manifest and re-check:
   `(cd lib/modules && shasum -a 256 *.ko > SHA256SUMS)` and
   `./scripts/check-artifacts.sh`;
4. update the provenance table above (device, kernel, toolchain);
5. before shipping, confirm the module agrees with the running kernel:
   `strings lib/modules/usbhid.ko | grep vermagic` must equal the kernel release
   printed by `cat /proc/version`.

`SHA256SUMS` is intentionally regenerated by hand — if `check-artifacts.sh` reports
a hash mismatch, either a blob was replaced without updating the manifest, or
the manifest was not regenerated after a deliberate swap.
